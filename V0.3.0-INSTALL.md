# Let's Trade ZM — V0.3.0
Customer Authentication & Dashboard

## Important
This package is designed to be added to the existing repository. It does NOT replace your existing PriceList, signup, payment, admin, or Firebase configuration files.

## Files
- login.html — customer email-link / phone-OTP login
- js/login.js — Firebase Authentication login
- dashboard.html — authenticated customer dashboard
- js/dashboard.js — UID-scoped subscription loading
- css/login.css — login page styles
- css/dashboard.css — dashboard styles

## Firebase requirement
Your existing `js/firebase.js` must export:
`app`, `db`, and `auth`.

The current project already has this structure.

## Firebase Authentication
Enable:
1. Email link (passwordless)
2. Phone

For phone authentication, Firebase requires reCAPTCHA and an authorized domain. Add:
`mwizamk.github.io`
to Firebase Authentication > Settings > Authorized domains.

For email-link authentication, add your GitHub Pages URL as an authorized domain and enable Email/Password provider with email-link enabled.

## Critical customer-link requirement
A customer can only reach the dashboard when the authenticated Firebase UID exists in:
`clients/{clientId}.customerUid`

Therefore V0.3 login is intentionally NOT based on simply typing a phone/email and reading another customer's records.

Your signup flow must eventually create/link the Firebase Auth UID to the client record. If your current signup still creates anonymous users, V0.3 authentication will not link correctly across devices. That is the next integration step after installing this package.
